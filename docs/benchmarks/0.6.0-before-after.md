# 0.6.0 before and after

A one-off comparison of Blacksmith with its own earlier builds, measured on
2026-11-03. It is not a comparison with plain Claude Code. That comparison is
still not measured; see [Not a comparison with plain Claude Code](#not-a-comparison-with-plain-claude-code).

## Method

- **Before:** 2026-09-01 to 2026-10-21, on builds before 0.6.0. 243 finished
  tasks, 153 waves, many epics on several projects.
- **After:** 2026-10-29 to 2026-11-03, on the 0.6.0 build. 38 finished tasks,
  26 waves, two Blacksmith epics (bs-gate-bounce, bs-check-tiers). Both were
  epics about the factory itself, with long specs, plan amendments and several
  closing-review passes.
- **Sources:** the factory's event log and Claude Code transcripts, read
  locally. Only counts, ids, timestamps, roles and sizes were kept. The raw
  extracts are not published because they come from local transcripts.

## Parallelism and time

| Metric | Before | After |
|---|---|---|
| Share of active wave time with only one agent busy | 67.6% | 29.8% |
| Merge to next wave admitted, median | 14.7 min | 2.6 min |
| Judges that ran one after another instead of together | 42.4% | 12.1% |
| Share of gate runs that blocked | 43.7% | 11.6% |
| Check command, median | 469 s | 181 s |
| Wave admitted to merged, median | 0.99 h | 1.00 h |
| Task wall time, median / p90 | 1.35 h / 16.1 h | 1.50 h / 16.7 h |
| Waves with a single task (worse) | 56% | 73% |
| Peak live agents | 10 | 6 |

## Quality

| Metric | Before | After |
|---|---|---|
| S1 / S2 / S3 / S4 findings per task | 0.02 / 0.07 / 0.51 / 0.21 | 0 / 0.18 / 1.89 / 0.29 |
| Reviewer rounds per task, mean | 1.49 | 2.55 |
| Coder dispatches per task, mean | 1.70 | 2.50 |
| Grader fail rate | 1.24% | 0% |

The finding and round rises coincide with these two epics. They ran under a
rule that every S3/S4 is fixed and none waived, and they used opus reviewers
for depth. The data cannot separate that from the version change.

## Tokens

| Metric | Before | After |
|---|---|---|
| Cache-read share of tokens | 0.94 | 0.97 |
| Lessons block in a brief, median size | 22.9k chars | 14.6k chars (-36%) |
| Tokens per agent dispatch, median, without output tokens | 160k | 182k (x1.14) |

- **Weighting:** tokens are weighted as input x1, cache write 5m x1.25, cache
  write 1h x2, cache read x0.1, output x5.
- **Output is excluded** because Claude Code 2.1.305 and earlier recorded
  output tokens at stream start (a median of 8 per call), while 2.1.312 and
  later record the full count (a median of about 350). With output as
  recorded, the median reads 160k to 239k (x1.49), but most of that gap is the
  recording change.
- **Where the x1.14 comes from:** longer contexts (the 633k compact window
  means sub-agents no longer compact), planner resumes after the cache
  expired, opus reviewers, and more rounds per task.
- **Real spend of bs-check-tiers,** counted as input + cache write + output
  from its sub-agent transcripts: about 38M tokens for 23 merged tasks. The
  factory's own budget log had recorded 0.48M of that, because it counts only
  workers' self-reported usage. A fix is planned.

## Caveats

- The samples are small (38 vs 243 tasks) and the epics differ in kind.
- Output tokens are not comparable across Claude Code 2.1.305 and 2.1.312.
- Per-merged-task token cost could not be computed for the after window,
  because both epics were planned before it began.
- One time metric, the median of full unit-suite commands, was dropped as
  unreliable.
- Two numbers got worse: waves with a single task, and task wall time. Wave
  admitted to merged did not change.
- This is a one-off measurement, not a recurring benchmark.

## Not a comparison with plain Claude Code

This is not a comparison with plain Claude Code. That needs the trial kit
([`docs/trial/methodology.md`](../trial/methodology.md),
[`trial/README.md`](../../trial/README.md)), which has not been run. Until it
is, the plain-versus-Blacksmith comparison is NOT MEASURED.
